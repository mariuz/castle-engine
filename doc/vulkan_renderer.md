# Vulkan 1.3+ Rendering Backend & Render Hardware Interface (RHI)

## 1. Overview & Architecture

Castle Game Engine (CGE) provides a modern, high-performance Vulkan 1.3+ (up to Vulkan 1.4) rendering backend alongside its established OpenGL and OpenGLES backends. This implementation introduces an extensible Render Hardware Interface (RHI) layer that unifies GPU abstractions while maintaining 100% backward compatibility with CGE's scene graph (`TCastleViewport`, `TCastleScene`, `TCastleTransform`), 2D/3D viewports, and UI controls (`TCastleUserInterface`, `TDrawableImage`).

```
+-----------------------------------------------------------------+
|          Castle Game Engine High-Level Systems                  |
|    (TCastleViewport, TCastleScene, TCastleTransform, 2D UI)     |
+-----------------------------------------------------------------+
                               |
                               v
+-----------------------------------------------------------------+
|            Render Hardware Interface (RHI)                      |
|  (TRHIDevice, TRHIBuffer, TRHITexture, TRHIPipeline, Commands)  |
+-----------------------------------------------------------------+
              /                                     \
             v                                       v
+-------------------------+             +-------------------------+
|    Vulkan 1.3+ RHI      |             |     OpenGL / ES RHI     |
| (Dynamic Rendering,     |             | (State cache, VAO/VBO,  |
|  Negative Viewport,     |             |  Uniform Buffers,       |
|  Sub-allocator, WSI)    |             |  FBO compatibility)     |
+-------------------------+             +-------------------------+
```

### Key Highlights
- **Vulkan 1.3+ Core & Dynamic Rendering**: Fully utilizes `VK_KHR_dynamic_rendering` (core in Vulkan 1.3) with automatic fallback to cached `VkRenderPass`/`VkFramebuffer` on Vulkan 1.1/1.2 devices.
- **Zero Static C/C++ Dependencies**: Vulkan API functions are dynamically loaded at runtime using Free Pascal's `TDynLib` (`vulkan-1.dll` on Windows, `libvulkan.so.1` on Linux/Android, `libMoltenVK.dylib` on macOS/iOS) from headers auto-generated by `tools/internal/generate_vulkan_api/vkxml2pas.dpr`.
- **Sub-Allocation GPU Memory Manager**: Pure Object Pascal sub-allocator (`TCastleVulkanMemoryAllocator`) allocating large 64 MB (device local) and 16 MB (host visible) blocks to strictly respect Windows/driver 4,096 `maxMemoryAllocationCount` limits.
- **Unified NDC Coordinates & Negative Viewport**: Exploits `VK_KHR_maintenance1` negative viewport height (`Viewport.Y = Height; Viewport.Height = -Height`) so CGE's coordinate conventions (Y-up, CCW winding) work naturally without vertex shader inversion hacks.
- **Runtime SPIR-V Compilation, Pure Pascal Reflection & Pipeline Caching**: Integrates dynamic `libshaderc` loading with persistent disk caching (`castle-config:/shader_cache/`), pure Pascal SPIR-V reflection (`InspectSPIRVBytecode`), `VkPipelineCache` (`castle-config:/vulkan_pipeline_cache.bin`), and `VK_EXT_graphics_pipeline_library` 4-part fast linking.
- **Cross-Platform Native `VkSurfaceKHR` Window Integration**: Automatic native surface creation in `TCastleWindow` across Win32 (`vkCreateWin32SurfaceKHR`), Linux X11 (`vkCreateXlibSurfaceKHR`), Linux Wayland (`vkCreateWaylandSurfaceKHR`), Android (`vkCreateAndroidSurfaceKHR`), macOS/iOS MoltenVK (`vkCreateMetalSurfaceEXT`), and Nintendo Switch (`vkCreateViSurfaceNN`).
- **Next-Gen Rendering Subsystems**: Declarative Render Graph (`TRHIRenderGraph`), GPU-Driven Meshlet/Hi-Z Culling, Clustered Forward+ Lighting, Virtual Shadow Maps (VSM) & PCSS, Lumen Global SDF & Surface Cache, DDGI Probes, ReSTIR GI, TSR & TAA, GTAO, Hi-Z SSR, Froxel Volumetric Fog, Atmosphere Sky-View LUT, Gerstner Ocean & Single-Layer Water, Hardware Ray Tracing (`VK_KHR_ray_query` & `VK_KHR_ray_tracing_pipeline`) + SVGF & Neural MLP Denoising, 3D Gaussian Splatting, and Order-Independent Transparency (WBOIT & Per-Pixel Linked List OIT).

## 2. Render Hardware Interface (RHI)

The RHI abstraction lives in `src/base_rendering/rhi/` and `src/base_rendering/vulkan/`:

| Unit | Description |
| :--- | :--- |
| `CastleInternalRHI` | Device, buffer, texture, sampler, pipeline, query pool, render graph, and command list abstractions. |
| `CastleInternalShaderRHI` | GLSL 450 shader generator, UBO/SSBO layout management, push-constant bindings, PBR/next-gen BSDF & compute shader generators. |
| `CastleInternalBatch2DRHI` | High-throughput 2D sprite/quad batch renderer with streaming vertex buffers and push constants. |
| `CastleInternalRenderDoc` | In-application RenderDoc frame capture and replay UI integration. |
| `CastleInternalVulkan` | Auto-generated dynamic loader, types, enums, structs, and Vulkan 1.0–1.4 API entry points. |
| `CastleInternalVulkanWSI` | Cross-platform Window System Integration (WSI) for Win32, X11, Wayland, Android, Metal/MoltenVK, and Nintendo Switch. |
| `CastleInternalVulkanMemory`| Pooled linear/non-linear sub-allocation GPU memory manager (`TCastleVulkanMemoryAllocator`) & ring buffers. |
| `CastleInternalRHI_Vulkan` | Complete Vulkan 1.1–1.4 backend implementation of RHI interfaces and next-gen GPU subsystems. |
| `CastleInternalRHI_OpenGL` | OpenGL / OpenGLES backend adapter for parity and visual regression validation. |
| `CastleInternalShaderCompiler` | Dynamic `libshaderc` wrapper, pure Pascal SPIR-V reflection inspector, and persistent disk cache. |

## 3. High-Level `TCastleRenderOptions` & `TCastleViewport` Configuration

Selecting the Vulkan backend can be done in `CastleEngineManifest.xml`:
```xml
<project name="my_game" render_backend="vulkan">
```
or in Pascal code before opening the window:
```pascal
ApplicationProperties.RenderBackend := backendVulkan;
```

### Per-Scene Options (`TCastleScene.RenderOptions`)
- `SpecularAntiAliasing: Boolean` (default `True`) — Normal-variance roughness filtering (Kaplanyan/Toksvig).
- `DualQuaternionSkinning: Boolean` (default `False`) — Volume-preserving Dual-Quaternion Skinning (DQS) on articulated joints.
- `GpuDrivenMeshletCulling: Boolean` (default `False`) — 64-vertex / 124-triangle meshlet cone/sphere and Nanite Cluster DAG culling.
- `TransparencyMode: TTransparencyMode` (`tmAlphaBlending`, `tmWeightedBlendedOIT`, `tmPerPixelLinkedListOIT`).
- `ShadowMapSystemMode: TShadowMapSystemMode` (`smsStandardShadowMaps`, `smsPCSSContactHardening`, `smsVirtualShadowMaps`).

### Per-Viewport Options (`TCastleViewport`)
- `GlobalIlluminationMode: TGlobalIlluminationMode` (`giNone`, `giDDGIProbes`, `giVoxelConeTracing`, `giLumenSDFAndSurfaceCache`, `giReSTIRGI`).
- `TemporalAntiAliasingMode: TTemporalAntiAliasingMode` (`taaNone`, `taaStandardTAA`, `taaTSRUpscaler`).
- `VariableRateShadingMode: TVariableRateShadingMode` (`vrsNone`, `vrsContrastAdaptive`, `vrsFoveatedStereo`).
- `NextGenToneMappingMode: TNextGenToneMappingMode` (`ntmStandard`, `ntmAgXGamutCompressed`, `ntmHDR10Rec2020PQ`).
- `VolumetricFogEnabled: Boolean`, `AutoExposureEnabled: Boolean`.
- Physical Camera Exposure: `CameraApertureFStops` (default `16.0`), `CameraShutterSeconds` (default `0.008`), `CameraISO` (default `100.0`), `EvaluateCurrentCameraEV100`, and `EvaluateCurrentCameraExposureMultiplier`.
- `TargetFrameRateHz: Single` — GPU frame pacing target rate (`0.0` = uncapped).

## 4. Coordinate System & Negative Viewport

Vulkan's default clip space uses a right-handed system with the Y-axis pointing downwards ($[-1, 1]$ in X and Y, and $[0, 1]$ in Z). OpenGL uses Y pointing upwards and $[-1, 1]$ in Z.

To ensure shaders, models, and UI elements produce identical results across backends without altering vertex shaders:
1. **Y-Axis Inversion**: We configure Vulkan viewports using negative height:
   ```pascal
   VkViewport.x := ViewportRect.Left;
   VkViewport.y := ViewportRect.Bottom + ViewportRect.Height;
   VkViewport.width := ViewportRect.Width;
   VkViewport.height := -ViewportRect.Height;
   VkViewport.minDepth := 0.0;
   VkViewport.maxDepth := 1.0;
   ```
2. **Z-Axis Depth Remapping**: When generating GLSL 450 shaders for Vulkan, depth coordinates are mapped to Vulkan's $[0, 1]$ range via `TCastleShaderGeneratorRHI.FinalizeVertexShaderSource`:
   ```glsl
   gl_Position.z = (gl_Position.z + gl_Position.w) * 0.5;
   ```

## 5. Descriptor Set Layout Strategy

Shaders adhere to a standard 4-set frequency-based binding convention:

| Set | Frequency | Contents |
| :---: | :--- | :--- |
| **Set 0** | Per-Frame | Camera View/Projection matrices, elapsed time, ambient light, multi-light UBO, fog parameters. |
| **Set 1** | Per-Pass / Material | Material parameters, albedo/normal/metallic-roughness/emissive textures, samplers (or bindless index). |
| **Set 2** | Per-Object / Node | Model transform matrix, normal matrix, bone matrices (`TCastleSkinningUBO`) for skeletal animation. |
| **Set 3** | Per-Draw / Dynamic | Push constants (`TCastlePushConstants`), dynamic sprite tints, 2D batch offsets. |
